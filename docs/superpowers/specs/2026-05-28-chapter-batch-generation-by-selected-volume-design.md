# 章节正文批量生成改为卷内定量生成设计

Date: 2026-05-28

状态：待用户审阅

## Problem

当前 `章节正文` 的批量生成界面仍然要求用户手填：

- 卷号
- 章节范围
- 并发数

这与实际入口不一致。用户已经通过左侧卷列表进入当前卷，卷号不应该再次输入；章节范围也不应该再手工指定，因为该卷的章节总数已经由章节大纲确定；并发数和生成数量也不应该拆成两个概念，用户只需要决定这次要补多少章。

## Goals

- 进入某一卷后，批量生成界面不再显示卷号输入。
- 批量生成界面不再显示章节范围输入。
- 批量生成界面不再显示并发数输入。
- 页面只显示当前卷的总章数、已生成章数、剩余章数。
- 用户只填写“生成数量”。
- 当用户输入的生成数量大于剩余章数时，自动按剩余章数截断。
- 生成从当前卷第一个未生成章节开始，顺序连续生成。
- 生成数量同时作为并发上限使用。

## Non-Goals

- 不改变章节正文列表页的正文读取规则。
- 不改变章节生成的核心写入图逻辑。
- 不改造章节大纲本身的章节规划结构。
- 不引入新的数据库或独立任务队列。

## Chosen Design

### 1. 入口以“当前卷”为前提

`章节正文` 的批量生成页继续沿用左侧卷列表作为入口。用户先选卷，再进入批量生成视图。卷号只是上下文，不再作为表单项出现。

页面内部保留当前卷状态，用于驱动：

- 该卷的章节总数
- 已生成章节数
- 剩余章节数
- `已生成章节` 列表的范围过滤

### 2. 表单只保留“生成数量”

批量生成面板只保留一个可编辑数值：

- `生成数量`

界面上方同步展示三项只读信息：

- 总章数
- 已生成章数
- 剩余章数

用户输入的值代表本次要尝试生成的章节数量，而不是章节区间。

### 3. 生成数量和并发数合并

生成数量就是并发数，不再单独提供 `max_workers`。

规则如下：

- 用户输入 `n`
- 实际生成数 = `min(n, 剩余章数)`
- 实际并发数 = `实际生成数`

这样可以保持界面简单，同时让用户对一次批量生成的规模有明确预期。

### 4. 起始章节由“第一个未生成章节”决定

批量生成永远从当前卷中第一个未生成章节开始。

例如：

- 当前卷总共 20 章
- 已生成 3 章
- 剩余 17 章

那么下一次批量生成会从第 4 章开始，按用户输入的生成数量继续向后生成。

如果中间存在缺口，后端应以本卷中最小的未生成章节作为起点，保证不会重复覆盖已生成章节。

## Data Model

批量生成页需要的核心数据不是“手填参数”，而是“当前卷摘要”。

建议由后端提供一个卷级批量生成上下文，至少包含：

- `volume_index`
- `volume_label`
- `total_chapters`
- `generated_chapters`
- `remaining_chapters`
- `next_chapter_number`
- `chapter_items` 或等价的卷内已生成章节列表

其中：

- `total_chapters` 来自当前卷章节大纲定义的章节总数
- `generated_chapters` 来自该卷已经落地的章节记录
- `remaining_chapters = total_chapters - generated_chapters`
- `next_chapter_number` 是当前卷第一个未生成章节

如果当前卷没有可解析出的章节总数，批量生成按钮应禁用，并显示该卷章节规划缺失。

## Backend Contract

### Generation Request

批量生成请求仍然需要携带当前卷的上下文，但这个值来自左侧卷选择，不再由用户输入。

新的请求语义建议为：

- `volume_index`: 当前卷
- `requested_count`: 用户输入的生成数量

后端收到请求后负责：

- 读取当前卷的章节总数
- 读取已生成章节数
- 将 `requested_count` 截断到剩余章节数
- 设置并发上限等于实际生成数
- 从 `next_chapter_number` 开始批量生成

如需兼容旧接口，旧字段可以继续接收，但前端不再发送卷号输入、章节范围输入和并发数输入。

### Workspace Summary

批量生成页需要一个卷级摘要来源。设计上可以复用现有章节大纲数据和卷内章节列表，但前端应以一个统一的摘要对象渲染 UI，而不是在页面内自行拼接多份零散数据。

这个摘要对象应足够支持：

- 顶部统计展示
- 生成按钮启停
- `已生成章节` 页签内的卷过滤

## Frontend Behavior

### Batch Panel

批量生成页显示：

- 当前卷名称
- 总章数
- 已生成章数
- 剩余章数
- `生成数量` 输入框
- `生成章节` 按钮

批量生成页不再显示：

- 卷号输入
- 章节范围输入
- 并发数输入

### Validation

- `生成数量` 默认最小值为 1
- 若输入为空或非法，前端应恢复为 1 或提示校正
- 若输入大于剩余章数，提交前或后端执行时自动截断为剩余章数
- 若剩余章数为 0，按钮禁用

### Generated Chapter List

`已生成章节` 继续沿用当前卷过滤结果，只显示该卷范围内的已生成章节。

切换到其他卷时：

- 批量生成摘要刷新
- 已生成章节列表刷新
- 选中的章节详情清空或切换到该卷的首个章节

## Error Handling

- 如果当前卷缺少章节总数信息，批量生成页应明确提示，而不是让用户盲填。
- 如果当前卷已经没有剩余章节，按钮应保持禁用，避免重复提交。
- 如果后端拒绝生成，前端保留当前输入值，方便用户调整数量后重试。

## Testing

需要覆盖以下点：

1. 前端批量生成页不再渲染卷号、章节范围、并发数输入。
2. 前端会展示总章数、已生成章数、剩余章数。
3. 用户输入大于剩余章数时，提交值会被截断到剩余章数。
4. 后端批量生成逻辑会从第一个未生成章节开始。
5. 当剩余章节为 0 时，批量生成按钮不可用。

## Scope Check

这是一个单点改版，范围集中在 `章节正文` 的批量生成面板及其对应的卷级摘要来源，不需要拆成多个子项目。
